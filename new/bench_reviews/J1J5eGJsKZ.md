## Summary
ToolDial introduces a multi-turn dialogue dataset of 11,111 dialogues (avg. 8.95 turns) for evaluating tool-augmented language models. The key technical contributions are: (1) an API graph constructed from RapidAPI based on input-output compatibility, enabling chained API usage; (2) a 16-action taxonomy with 23 predefined action sequences to capture diverse user-system interactions including clarifying questions, failed information, and proactive API calls; and (3) a four-step generation pipeline that converts action skeletons into natural dialogues via GPT-4o. Evaluation reveals that modern LLMs achieve below 70% accuracy on dialogue state tracking and action prediction, while fine-tuning Llama3-8B on ToolDial yields substantial improvements.

## Strengths
- **Well-motivated gap in existing benchmarks.** ToolDial addresses a genuine need: prior TALM benchmarks (ToolBench, API-Bank, ToolAlpaca) average only 2–2.84 turns per dialogue with 3–7 action types, while ToolDial provides 8.95 avg. turns and 16 action types. The focus on scenarios like "Fail inform" and chained API calls addresses realistic interaction patterns missing from existing datasets.

- **Systematic and principled data generation pipeline.** The four-step pipeline (graph construction → action sequences → scenario generation → dialogue generation) is well-structured, reproducible, and informed by TOD literature. The API graph construction (Eq. 1) using embedding similarity, keyword-augmented similarity, and LCS with explicit thresholds is a thoughtful approach to matching API outputs to inputs across 4,474 APIs.

- **Insightful per-action evaluation.** Table 5 reveals specific weaknesses of GPT-family models—near-zero F1 on "Clarify," "Suggest," and "Response fail"—demonstrating that models rush to answer without collecting information or asking clarifying questions. This is a meaningful empirical finding for the community.

- **Demonstrated training utility.** TD-Llama (Llama3-8B fine-tuned on ToolDial) dramatically outperforms zero-shot baselines on action prediction (91.0% w/o GT vs. ~60% for GPT models), showing the dataset serves both evaluation and training purposes.

- **Graph evaluation is quantitatively grounded.** The MCC of 0.868 against human judgment and NPV of 95% provide concrete evidence for the API graph's quality, rather than relying solely on qualitative assessment.

## Weaknesses

### Major:
- **Faithfulness evaluation is structurally circular.** The faithfulness scores in Table 4 (>95% for GPT models) are evaluated entirely by GPT-4o-mini via G-Eval, with no human or rule-based verification on model outputs. Since the dialogues are generated by GPT-4o and several evaluated models are in the same family, this creates circularity: models from the same training distribution are judging each other. The paper does not establish that G-Eval is reliable for this specific task. This problem is partially acknowledged for data quality evaluation (Table 3) but not for the primary experimental faithfulness results. Consequently, the conclusion that "faithfulness is essentially solved" while "state/action prediction is the bottleneck" is not adequately supported.

- **Limited validation of the fully synthetic dataset.** Only 100 of 11,111 dialogues were human-evaluated (Table 3), with no inter-annotator agreement reported and no stratified sampling across action sequences or API chain complexity. Given that the entire dataset—including user queries, dialogue states, and utterances—is GPT-4o-generated, and that subtle but crucial aspects (parameter consistency across turns, semantic correctness of chained API scenarios, plausibility of "Fail inform" situations) would be unlikely to surface in an untargeted small-sample evaluation, the central claim that ToolDial captures "realistic" tool-use dynamics is inadequately validated. This is a common issue in the field but is exacerbated by the paper's strong "real-world" framing.

- **Unexplained w/o GT outperforming w/ GT for TD-Llama action prediction.** Table 4 shows TD-Llama achieves 91.0% without ground-truth labels but only 77.5% with ground-truth labels on action prediction. This is counterintuitive—removing oracle information should not help—and the paper offers no explanation (Section 4.3). This anomaly raises questions about the evaluation setup, such as whether the "w/ GT" setting introduces format mismatches or whether prior GT labels confuse the fine-tuned model, and directly undermines confidence in the reported numbers.

### Minor:
- **API graph precision at 70.9% with incomplete disclosure of downstream filtering.** The paper states that invalid edges are "discarded in subsequent steps" (§3.1) but does not describe the systematic method for identifying and removing the ~29% invalid edges across the full 4,857 edges. The evaluation was done on 200 sampled edges (MCC 0.868), but it is unclear how thoroughly the remaining edges were validated. While the NPV of 95% provides confidence that few valid edges are missed, recall (coverage of true edges) is never estimated, leaving uncertainty about graph completeness.

- **Restricted to API pairs rather than longer chains.** The dataset only chains two APIs at a time, whereas real-world tool use can involve longer sequential dependencies. The paper does not justify this design choice or discuss its implications for the dataset's ability to test deeper reasoning.

- **"Real-world" and "realistic" claims are overstated for a fully synthetic dataset.** The introduction and conclusion repeatedly assert that ToolDial reflects "real-world scenarios" and "realistic interactions," but all dialogues are GPT-4o-generated from template-driven action sequences. While the scenarios modeled are inspired by realistic use patterns, there is no empirical evidence that the distribution of actions, queries, or failure modes matches actual user behavior. This language should be softened.

### Trivial:
- The DST exact-match metric after normalization may penalize semantically equivalent but lexically different predictions, though this is a clear and defensible choice for a benchmark.

## Nice-to-Haves
- Cross-benchmark evaluation (e.g., testing ToolDial-trained models on API-Bank or ToolTalk) to demonstrate the dataset's distinctive value and cross-domain transferability.
- Analysis of action sequence distribution across the 11,111 dialogues (how many fall into each of the 23 types?) to verify that the "rich dynamics" claim holds in practice.
- Release the API graph as a standalone resource; it could be useful beyond this dataset.
- Report inter-annotator agreement for the 100-dialogue human evaluation.
- Investigate the anomalous w/o GT > w/ GT result for TD-Llama.

## Removed Points
These points are flagged to be removed, treat them with caution:
- **Demands for reproducibility details** (thresholds, hyperparameters): The paper references thresholds for emb/LCS in Appendix A.2. Reproducibility concerns about implementation details are standard for benchmark papers and don't undermine the core contribution.
- **Criticism that the w/ GT setting "assumes oracle information no real system would have"**: The paper explicitly frames w/ GT as an "upper bound" and w/o GT as "better reflecting real-world scenarios." This is a valid experimental design choice, not a flaw. The harsh reviewer's objection that w/ GT is not a "clean upper bound" has some merit but overstates the problem—both settings provide useful information.
- **Demand for human performance ceiling**: The claim that "substantial room for improvement" requires a human ceiling is scope creep; the paper's conclusion is adequately supported by the absolute model performance levels.
- **Questioning whether models behave differently because "gold actions are template-driven"**: This is speculative without evidence that the template actions are truly suboptimal for the described scenarios.
- **GPT-4o data contamination / memorization concerns**: The suggestion that GPT-4o's performance reflects memorization of its own generation patterns is speculative; no evidence is presented, and this concern applies broadly to all synthetic benchmarks.
- **Demand for NLI-based faithfulness metric**: While alternative metrics would strengthen faithfulness evaluation, G-Eval is a widely-used approach in this research community, making this a nice-to-have rather than a core flaw. The core flaw is the circularity of using same-family models, not the specific metric choice.

## Novel Insights
The finding that GPT-family models systematically avoid "Request" and "Clarify" actions (F1 near 0 in Table 5) while fine-tuning on ToolDial dramatically improves these specific actions is genuinely interesting. It suggests that current instruction-tuned models have a behavioral bias toward answering immediately rather than gathering information—a pattern that is not well-documented in the TALM literature and has practical implications for deploying tool agents in real conversational settings. The 28.3% full-dialogue accuracy for TD-Llama (despite 77.1% per-step accuracy) also highlights how errors compound across turns, a crucial but underappreciated challenge.

## Suggestions
- Replace or supplement G-Eval with a rule-based or human-verified faithfulness evaluation on at least a sample of model outputs to address circularity concerns.
- Analyze the w/o GT vs. w/ GT anomaly for TD-Llama—inspect whether GT labels introduce task format confusion, and report prompt details for both settings.
- Report the distribution of dialogues across the 23 action sequences to verify diversity, and provide a breakdown of model performance on chained vs. single-API dialogues.
- Tone down "real-world" and "realistic" claims throughout the paper, replacing them with "simulates realistic interaction patterns" or similar hedged language.
- Add inter-annotator agreement to the human evaluation section.

## Score and Decision

Calibration against similar papers:
- **ToolLLM** (Accept Spotlight, 6-8): Larger scale (16K APIs), more extensive evaluation, but similar reliance on ChatGPT evaluation and synthetic data. ToolDial has a more structured pipeline and richer action taxonomy but smaller scale and weaker evaluation methodology.
- **τ-bench** (Accept Poster, 6-8): More rigorous end-state evaluation (database state comparison vs. G-Eval), two real-world domains. Smaller but more rigorously evaluated.
- **MTU-Bench** (Accept Poster, 5-6): Similar scope (benchmark paper, synthetic data, multi-turn), comparable weaknesses. ToolDial has more novelty in its pipeline but similar validation limitations.
- **TaskBench** (Reject, 3-6): Synthetic benchmark with tool graph, suffered from data quality issues and limited validation—similar concerns to ToolDial but more severe.

ToolDial sits between MTU-Bench and ToolLLM/τ-bench in quality. It has genuine novelty in the action taxonomy and API graph, and useful empirical findings. However, the circular faithfulness evaluation, limited human validation, and unexplained evaluation anomaly are substantive weaknesses that prevent a stronger assessment. The paper makes a real contribution to the TALM benchmark landscape but does not fully deliver on its "real-world" claims.
