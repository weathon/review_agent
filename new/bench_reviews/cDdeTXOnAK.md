## Summary

AutoCoder introduces AIEV-INSTRUCT, a code instruction dataset generation pipeline that couples GPT-4 Turbo as a teacher with a Docker-based execution verification loop and a two-stage Teaching/Self-Learning design that eventually replaces the proprietary teacher with the student model itself. The resulting AutoCoder-33B achieves 90.9% Pass@1 on HumanEval and is presented as surpassing GPT-4 Turbo and GPT-4o. The paper's central scientific claim—that execution-verified multi-turn data enables a 33B model to exceed frontier proprietary models—is partially supported by strong ablations but is significantly overstated in the headline framing.

---

## Strengths

- **Execution-verified data generation pipeline (Section 3.1, Figure 3):** AIEV-INSTRUCT runs generated code in a Docker environment, feeds stderr/stdout back to the agent iteratively (up to 7 rounds), and only retains data that passes unit tests. This directly and concretely addresses the unverified-code problem in prior methods like EVOL-INSTRUCT and OSS-INSTRUCT.

- **Ablation evidence for execution feedback (Figure 6):** The controlled four-level ablation (Base → Base+ST → Base+MT → Base+EFMT) shows that execution feedback with unit tests provides a 10.1 percentage-point gain on HumanEval (81.3% → 91.4%) for the 33B model, substantially larger than the gain from adding multi-turn structure without execution feedback (~0.0 points). This is concrete evidence that the core method contributes beyond dataset scale or format.

- **Two-stage self-learning design (Section 3.1):** The mechanism that switches from GPT-4 Turbo as teacher to the student model itself—triggered when the student surpasses the teacher on a held-out test set—is a well-motivated engineering design that reduces ongoing dependence on proprietary model inference costs.

- **State-of-the-art 33B open-source model:** AutoCoder-33B is the best 33B-scale model across HumanEval, HumanEval+, LiveCodeBench (Table 4: 25.4% vs. 23.4% for DeepSeek-Coder-Instruct-33B), and DS-1000. For practitioners constrained to open-source sub-70B models, this is a meaningful result.

- **Comprehensive multi-benchmark evaluation (Tables 1–4):** The paper evaluates across seven benchmarks including the contamination-resistant LiveCodeBench, six programming languages via MultiPL-E, and data science tasks via DS-1000.

## Weaknesses

### Fatal
None.

### Major

- **Headline claim "surpasses GPT-4 Turbo" is not supported by the evidence, and is contradicted by the paper's own stronger benchmarks.** The 0.7-point advantage on HumanEval corresponds to approximately 1.1 problems on a 164-item benchmark, with no statistical testing and no multi-run variance reported. More critically, HumanEval+ (which adds stronger test cases to reduce false positives) reverses the comparison decisively: AutoCoder 78.0% vs. GPT-4 Turbo 86.6%, an 8.6-point deficit. AutoCoder's drop from HumanEval to HumanEval+ (12.9 points) is by far the largest in Table 1, compared to GPT-4 Turbo's 3.6-point drop. The contamination-resistant LiveCodeBench (Table 4) shows a further 18.8-point deficit (25.4% vs. 44.2%). The pattern across benchmarks—narrow advantage on the most saturated/weakly-tested benchmark, clear deficits on all stronger evaluations—is consistent with benchmark-specific inflation rather than genuine superiority. The paper's framing (Abstract, Figure 1, Sections 1, 5.1) treats the HumanEval margin as a definitive result without acknowledging this pattern.

- **Ablation does not isolate the AIEV-INSTRUCT method from dataset scale.** Figure 6 compares Base+EFMT (the full AutoCoder dataset, 169K samples) against Base+ST and Base+MT, but the paper does not state whether Base+ST and Base+MT use the same 169K examples or the smaller Magicoder datasets (111K/75K). If ablation baselines use fewer samples, then the observed gains conflate dataset scale, multi-turn format, and execution verification. The critical missing control is: fine-tune DeepSeek-Coder-33B on 169K unverified single-turn instruction pairs generated by GPT-4 Turbo. Without this, it is impossible to attribute the gains to execution verification specifically versus volume.

### Minor

- **Self-learning stage transition criterion is partially circular (Section 3.1).** The decision to switch to self-learning is made when the student outperforms the teacher on a held-out subset of AIEV-generated data—which itself was produced by GPT-4 Turbo. Beating GPT-4 Turbo on its own generated examples does not reliably imply broader capability superiority, and the HumanEval/HumanEval+ and LiveCodeBench patterns raise the question of whether the self-learning stage is genuinely beneficial or only effective on the narrow distribution of training-derived test cases.

- **Large HumanEval → HumanEval+ performance gap is unexplained (Table 1).** AutoCoder's 12.9-point drop is the largest in the comparison set and deserves systematic analysis. Possible explanations—overfitting to weak test suites during self-learning, or data generation biased toward problems that pass minimal unit tests—are neither investigated nor acknowledged. Understanding this gap is important for knowing what AIEV-INSTRUCT actually teaches models to do.

- **Code interpreter "only model supporting automatic package installation" claim (Abstract, Section 1) is unverified.** This is presented as a distinct contribution but is evaluated only through one illustrative example (Figure 5) with no quantitative assessment of package installation success rate, robustness, or comparison to any baseline. It is a product claim, not a scientific one.

- **No statistical testing for marginal results.** Beyond the headline HumanEval claim, similar margin issues appear elsewhere: DS-1000 Matplotlib (AutoCoder 72.9% vs GPT-4 Turbo 72.3%; 0.6 points on ~155 problems), and MBPP/MBPP+ (AutoCoder trails GPT-4 Turbo by 3.2 and 2.7 points, not highlighted). Presenting all point estimates as definitive rankings without variance information is a systematic issue throughout the results section.

### Trivial

- The overall DS-1000 result (AutoCoder 47.2% vs. GPT-4 Turbo 53.9%, a 6.7-point deficit) is not highlighted while the Matplotlib subcategory win is given prominence. This selective presentation creates a misleading impression.

## Nice-to-Haves

- Add a matched-volume ablation: fine-tune DeepSeek-Coder-33B on 169K standard single-turn instruction pairs (no execution verification) to cleanly isolate the contribution of verification from scale.
- Report Pass@1 across multiple independent runs (different seeds) on HumanEval for any result cited as a head-to-head comparison, given the 164-problem benchmark size.
- Analyze execution-feedback loop statistics: what fraction of problems required 0, 1, 2, ..., 7 iterations? What fraction were discarded? This would illuminate whether AIEV corrects genuinely hard problems or only processes easy ones.
- Address the LiveCodeBench gap more directly in the analysis—perhaps by distinguishing which aspects of the training data help with algorithmic competition problems.

## Novel Insights

The most interesting observation from synthesizing the reviews is the systematic asymmetry in benchmark difficulty: AutoCoder's 12.9-point HumanEval→HumanEval+ drop is 3.5× larger than GPT-4 Turbo's 3.6-point drop. This pattern—strong performance on benchmarks with minimal test cases, weaker performance on benchmarks with thorough testing—is consistent with a training signal that teaches models to produce code that satisfies easy tests rather than deeply correct code. This raises a broader question about whether execution-verified data with unit tests generated by the same model that generates code (especially during self-learning) creates a closed loop where "correctness" is measured only against tests that can themselves be satisfied easily. If true, this would be an important limitation of the AIEV approach that warrants investigation.

## Suggestions

1. **Reframe the headline claim.** AutoCoder is demonstrably the best 33B open-source code model at the time of submission—that is a meaningful and defensible contribution. Framing it as "surpassing GPT-4 Turbo" on the basis of a sub-2-point HumanEval margin, while burying the HumanEval+ and LiveCodeBench deficits, undermines credibility. The paper would be stronger with honest positioning.

2. **Add matched-volume control to ablation.** This is the most important experiment for validating the paper's central methodological claim. Without it, reviewers cannot tell if AIEV-INSTRUCT's gains come from verification or simply from the larger dataset.

3. **Diagnose the HumanEval→HumanEval+ gap.** Analyze whether the gap shrinks if the training unit tests are made more comprehensive, or if the self-learning stage specifically amplifies it.
