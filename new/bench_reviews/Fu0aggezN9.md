## Summary

This paper introduces GraphDoc, a large-scale dataset (80K images, 4.13M relation annotations) for graph-based Document Structure Analysis (gDSA), extending DocLayNet to include both spatial and logical relations between document elements. It also proposes DRGG, a plug-and-play relation head for existing object detectors, achieving 57.6% mAP_g@0.5 as a baseline.

## Strengths

- **Novel and well-motivated task formulation**: The gDSA task—predicting both document element positions and their structural relations as a graph—is a meaningful extension beyond traditional DLA. The 8-relation-type taxonomy (4 spatial + 4 logical) is intuitive and fills a genuine gap, as existing datasets (Table 1) lack graph-structure annotations.

- **Large-scale dataset construction**: Creating 4.13M relation annotations over 80K pages from DocLayNet is a non-trivial engineering contribution. The task definition connecting DLA to graph generation is well-articulated, and the formulation enables reading order, hierarchy, and reference tasks under a unified framework.

- **Per-category analysis reveals important insights**: Table 3 provides per-relation AP breakdown, which honestly exposes the difficulty gap between spatial and logical relations, rather than hiding it behind an aggregate metric.

- **DLA improvement from relation context**: Table 2 shows that adding DRGG improves DLA mAP from 80.5% to 81.5%, suggesting that relational context provides some benefit for detection.

## Weaknesses

### Major:

1. **Annotation quality is unvalidated and derived from heuristics** — The 4.13M relations are generated by a rule-based pipeline (Sec 3.1.4) with only a vague claim that "most of the results have been manually verified and refined." No quantitative validation is provided: no inter-annotator agreement, no accuracy estimates, no error analysis per relation type. This is especially concerning for complex logical relations like "reference" (OCR-based text matching) and "parent/child" (hierarchy determined by heuristics). As the ADOPD reviewers and Chronicling Germany reviewers flagged for similar papers, lack of annotation quality verification undermines the benchmark's reliability. Since annotation quality is the foundation of a dataset paper, this is a significant gap.

2. **Evaluation metrics (mR_g, mAP_g) are insufficiently specified** — Algorithm 1 defines the evaluation pipeline but leaves critical details undefined. The function `f_mAP` is never specified; the paper claims "remaining settings align with standard SGG evaluation metrics" but simultaneously argues that standard ranking-based SGG metrics are inappropriate. The handling of multi-label relations per pair (spatial + logical coexisting) is unclear in how TP/FP are counted. The use of AP terminology with a fixed confidence threshold T_R is ambiguous—AP is conventionally computed over an entire PR curve, not at a single threshold. These ambiguities make the headline numbers hard to interpret and potentially over-optimistic, especially given the class imbalance.

3. **Inadequate baselines and ablations for gDSA** — All gDSA comparisons are variants of the same DRGG architecture paired with different detectors/backbones. There is no comparison against: (a) a simple pairwise MLP baseline, (b) existing scene graph generation methods adapted to documents, (c) text-based relation extraction approaches (e.g., LayoutLMv3 + relation head), or (d) the rule-based annotation pipeline itself as a baseline. Given that the annotations were generated by heuristics, comparing against those heuristics on the test set is essential to verify that DRGG learns beyond recovering annotation rules. No ablation of DRGG components (weighted token aggregation, pooling/upsampling) is provided, making it impossible to attribute performance to specific design choices.

### Minor:

4. **Class imbalance inflates aggregate metrics** — Spatial relations constitute 64% of all annotations and achieve near-perfect AP (99% for left/right), while critical logical relations like "reference" achieve only 16.8% AP. The headline mAP_g@0.5 of 57.6% is dominated by easy spatial relations, giving a misleading picture of document structure understanding. A "logical-only" mAP would be far more informative.

5. **Visual-only model on a task demanding textual understanding** — The paper acknowledges this limitation, but it remains odd that the proposed model cannot leverage text—the primary carrier of reference and hierarchical information—on a task explicitly designed to predict textual relationships (e.g., "this text references Figure 1"). The 16.8% AP on "reference" relations directly confirms this architectural mismatch.

6. **Dataset limited to single-page Manhattan-layout PDFs** — Cross-page relations are explicitly excluded, and the annotation rules assume Manhattan layouts. This limits generalizability to the full range of real-world document structures.

### Trivial:

7. **Equation 2 conflation** — The gDSA loss includes a node classification loss inside a sum over edges, conceptually conflating node and edge objectives. This is a minor notational issue, not a functional error.

## Nice-to-Haves

- Evaluate a geometry-only baseline (predict relations from bounding box coordinates alone) to establish whether learning is necessary for spatial relations.
- Report inter-annotator agreement or a subsample accuracy estimate for the heuristic annotations.
- Add a "logical-only" mAP metric to better track progress on the harder, more meaningful relations.
- Compare against text-based or multimodal methods (e.g., LayoutLMv3 + relation head) for the logical relations specifically.
- Include ablation studies isolating the contribution of DRGG's key components.

## Removed Points

These points are flagged to be removed, treat them with caution:

- **"Questionable baseline consistency" (Neutral Reviewer #3)**: The erratic AP on Left/Right (8.9% for DETR vs 99% for DeformableDETR) was flagged as anomalous. However, this is actually expected behavior: the relation prediction depends heavily on the quality of the underlying detector's object queries. DETR is a weaker detector and may not properly localize objects, leading to poor relation predictions. This is the same pattern seen in Table 2 where better detectors produce better gDSA results. Not a bug, just a reflection of detector quality.

- **"Unfair baseline comparison favoring authors" (Harsh Critic #3)**: The claim that comparisons are unfair because all baselines use DRGG is not really an unfair comparison—it's the only way to evaluate on the new gDSA task since no prior method predicts document relation graphs. The issue is actually about *insufficient* baselines (missing alternative relation heads), not unfair ones.

- **"Missing comparison with HRDoc/Comp-HRDoc" (repeated from Human Finder)**: HRDoc and Comp-HRDoc are for hierarchical structure analysis (parent-child only), not for full graph-based structure with 8 relation types. They would need significant adaptation to serve as baselines, and they operate at a different instance level (line-level vs paragraph-level). This is a nice-to-have but not a missing critical comparison.

## Novel Insights

The most insightful observation from the reviews is the tension between the dataset's ambition and its annotation methodology: GraphDoc proposes to measure deep document structure understanding, but annotates relations using heuristic rules that are largely recoverable from bounding box geometry (spatial relations) and surface text matching (references). The near-perfect 99% AP on left/right relations suggests these are trivially predictable from coordinates, while the 16.8% reference AP reveals that the truly semantic relations remain largely unsolved. This suggests the dataset's value lies more in its logical-relation annotations than its spatial ones, but the current metrics and model don't adequately separate or foreground this distinction.

## Suggestions

1. Report annotation quality statistics: sample 500-1000 pages, have two annotators independently label relations, compute inter-annotator agreement for each relation type. This is essential for a dataset paper.
2. Add a logical-only mAP metric (excluding spatial relations) to give a clearer picture of document structure understanding progress.
3. Include the rule-based annotation pipeline as a baseline on the test set, to verify that learned models outperform the heuristics that generated the training labels.
4. Add at least one simpler baseline for relation prediction (e.g., pairwise MLP on concatenated box features) to contextualize DRGG's contribution.

However, GraphDoc's gDSA formulation is cleaner than DocGenome's somewhat disconnected experiments, and the per-category analysis is more honest.

The paper makes a genuine contribution with the task formulation and dataset scale, but the unvalidated heuristic annotations, under-specified metrics, and absence of meaningful baselines are significant weaknesses for a dataset/benchmark paper where the benchmark itself must be trustworthy.
