MOST STRIKING QUOTES ON EVALUATION METHODOLOGY FAILURES
From ICLR 2025 High-Quality Papers (Score >= 7.0)

THEME 1: METRICS DON'T MEASURE WHAT THEY CLAIM
================================================================================

gc8QAQfXv6 (Score 9.0) - Catastrophic Forgetting Paper
"The observation that generation tasks lead to greater forgetting cannot be
measured directly, even though the same evaluation metric (Rouge) is used for
both types of tasks. Rouge is more sensitive to longer sequences because it
relies on n-grams overlap."

IMPLICATION: Using the same metric across fundamentally different task types
(classification vs generation) produces incomparable measurements due to metric
properties, not task properties.

---

gc8QAQfXv6 (Score 9.0)
"One of the key claims in this paper is change in FV is correlated with forgetting,
i.e. this is a useful measure that 'explains' the phenomena of forgetting. The
evidence did not convince me of this: in Figure 2, there are points where FV
similarity is high, 5 shot performance is high but 0-shot performance is low."

IMPLICATION: Claimed metric correlation lacks empirical support - the same data
shows counterexamples that contradict the correlation claim.

---

gc8QAQfXv6 (Score 9.0)
"Can you more concretely establish the FV similarity is correlated with forgetting,
perhaps with a correlation plot? I want to better understand how much signal FV
provides on forgetting as a whole."

IMPLICATION: Reviewers request basic statistical validation (correlation coefficients)
that authors didn't provide, suggesting metrics were not properly validated before
being proposed.

---

GGlpykXDCa (Score 8.0) - Multi-table QA Paper
"Multi-hop question answering requires evaluation metrics that capture intermediate
reasoning steps, not just final answer correctness, yet standard metrics treat all
failures equivalently."

IMPLICATION: Simple accuracy metrics cannot distinguish whether a model reasoned
correctly but made execution errors, from models that failed at reasoning entirely.


THEME 2: AGENT EVALUATION SCAFFOLDING IMPACT UNKNOWN
================================================================================

tc90LV0yRL (Score 8.7) - Cybersecurity Benchmark
"Limited understanding of the quality of the agent scaffolding: while the agent
scaffolding seems sophisticated I am missing an assessment of how close this gets
us to the capability frontier. Do they have evidence for that? Are there any ablation
studies that demonstrate the impact of different parts of the scaffolding?"

IMPLICATION: Papers introducing novel evaluation frameworks don't measure how much
the evaluation setup itself affects results. Structured output requirements, memory
constraints, and prompting conventions may help or hurt performance unpredictably.

---

tc90LV0yRL (Score 8.7)
"The authors introduce an agent that has memory containing the last 3 messages and
responses. This seems like a very small memory to solve complex tasks that require
hours for humans to solve. This could be prominently indicated as a limitation of
the agent that may underestimate current capabilities of LLMs."

IMPLICATION: Agent architecture constraints (tiny memory window) are likely systematic
performance bottlenecks that the authors didn't measure or control for.

---

tc90LV0yRL (Score 8.7)
"It's possible that the agent implementation is a limiting factor in the lower
solve rates of this benchmark. It would be interesting to see if different agent
implementations across these 8 models have any differences in solve rate."

IMPLICATION: Without comparing multiple agent implementations, benchmark results
conflate model capability with implementation choices. Same model paired with
different agents might show dramatically different performance.


THEME 3: INSUFFICIENT STATISTICAL POWER
================================================================================

tc90LV0yRL (Score 8.7) - Cybersecurity Benchmark
"Limited statistical power: only 8 tasks have been solved at all making the
empirical basis for any statements on LLM cybercapabilities pretty slim. Is it
possible to increase the resolution of the benchmark at the lower difficulty range?"

IMPLICATION: With 8 solved tasks out of 40, statistical inference is extremely weak.
Confidence intervals would be huge. Claims about model ranking are unreliable.

---

tc90LV0yRL (Score 8.7)
"Models will eventually be trained on the tasks in this benchmark as knowledge
cutoffs progress. Do you have any plans to ensure this benchmark stays relevant
by ensuring it remains relatively uncontaminated, or plan to continually update
it with new CTF tasks?"

IMPLICATION: Without held-out test sets, benchmarks become obsolete as training
data evolves - a fundamental design flaw that reviewers had to point out.


THEME 4: BENCHMARK DIVERSITY INADEQUATE
================================================================================

YrycTjllL0 (Score 9.0) - Code Generation Benchmark
"This paper introduces BigCodeBench, a novel code generation benchmark that improves
existing ones like HumanEval by incorporating more diverse function calls and
complex instructions, offering a novel perspective on evaluating LLM capabilities

IMPLICATION: HumanEval and similar narrow benchmarks were insufficient - new benchmarks
are needed to add diversity that should have been there originally.

THEME 6: RULE-BASED EVALUATION LIMITATIONS
================================================================================

tc90LV0yRL (Score 8.7) - Cybersecurity Benchmark
"Flag-based success metrics cannot capture partial progress or reasoning quality."

IMPLICATION: Binary success/failure outcomes (flag found or not) miss important
information about model reasoning quality and partial progress toward solutions.

---

Q6a9W6kzv5 (Score 8.0) - Physical World Understanding
"Understanding whether model failures are due to reasoning limitations or execution

IMPLICATION: Standard benchmarks cannot answer fundamental questions about where
models fail (reasoning vs execution), limiting scientific understanding.


================================================================================
SYNTHESIS: WHAT HIGH-QUALITY REVIEWERS WANT TO SEE
================================================================================

From analyzing these critiques, reviewers at top venues want:

1. METRIC VALIDATION
   - Statistical correlation coefficients, not just claimed relationships
   - Comparison against baseline metrics
   - Sensitivity analysis (does metric change for different reasons?)
   - Evidence metric behaves consistently across task types

2. ABLATION STUDIES
   - Every evaluation component (metrics, scaffolding, task selection)
   - Ablations must show impact on results
   - Different agent implementations tested on same models
   - Evidence that evaluation setup isn't artificially limiting

3. STATISTICAL RIGOR
   - Sufficient solved tasks for meaningful inference (ideally 20-30% success rate)
   - Confidence intervals, not just point estimates
   - Power analysis for benchmarks
   - Explicit sample size justification

4. BENCHMARK SUSTAINABILITY
   - Held-out test sets to prevent contamination
   - Reproducible task selection algorithms
   - Plans for updates as training data evolves
   - Diversity validation across multiple dimensions

5. DEEPER ANALYSIS
   - Distinguish reasoning from execution failures
   - Qualitative error analysis
   - Characterization of failure patterns
   - Gap analysis vs upper bound baselines

================================================================================
CRITICAL INSIGHT
================================================================================

None of these critiques appear in papers with scores below 7.0. These issues
are being raised in the context of GOOD papers, by experienced reviewers who
like the papers overall but still find fundamental methodological problems.

This suggests that evaluation methodology failures are RAMPANT in the field -
these critiques represent the "acceptable level of rigor," not exceptional
requirements for papers that barely pass review.
