BLUEPRINT-BENCH: 6 CRITICAL WEAKNESS PATTERNS FROM RELATED PAPERS
================================================================================

WEAKNESS #1: MULTI-VIEW INCONSISTENCY
─────────────────────────────────────
Title: Models produce inconsistent floor plans from different apartment images

What happens:
  - Same apartment photographed from different angles
  - Model given Image A generates floor plan X
  - Model given Image B (same apartment) generates floor plan Y
  - X ≠ Y, causing benchmark evaluation to be meaningless

Why it matters:
  - Blueprint-Bench provides 20 images per apartment
  - All 20 should yield identical floor plans
  - Inconsistency makes results unreliable

Source Quote:
  "BLIP-2 to answer these questions results in varied responses 'to protect them
  from splinters', 'to protect the horse's legs', 'to make the hooves more
  visible' for the three questions considered. This is problematic as the models'
  outputs may vary with the phrasing of a query rather than its actual intent,
  which undermines their reliability."
  — MM-R (70YeidEcYR)

How to test:
  Run Model(Apartment_A, Image_1) and Model(Apartment_A, Image_5).
  Check if floor graphs are identical. Large divergence = failure.


WEAKNESS #2: VISUAL PERTURBATION SENSITIVITY
──────────────────────────────────────────────
Title: Models fail when viewing conditions change (angle, lighting, distance)

What happens:
  - Same apartment room recognized from close distance
  - Same room unrecognized from far distance
  - Lighting/angle changes cause model to identify different spatial features
  - Model's spatial understanding collapses under visual variation

Why it matters:
  - Blueprint-Bench photos span multiple distances and angles
  - Some images taken from far back, others from tight corners
  - Model should handle all variations equally

Source Quote:
  "mPLUG-Owl2 is much more susceptible to inconsistency when image inputs are
  perturbed while MoE-LLaVa is more consistent in the change of the visual domain
  than the lingual domain. We find that SoTA MLLMs while often quite competitive
  in accuracy can differ substantially in their consistency of responses."
  — MM-R (70YeidEcYR)

How to test:
  Apply transformations to apartment images: zoom in/out, rotate, change
  brightness. Re-run model. Performance should remain stable. Significant
  drops indicate perturbation sensitivity.


WEAKNESS #3: SPATIAL ENTITY HALLUCINATION
───────────────────────────────────────────
Title: Models invent rooms, doors, or connections not present in photos

What happens:
  - Model claims apartment has room that doesn't exist in any photo
  - Model describes doorway between rooms with no visible connection
  - Model generates floor plan features unsupported by visual evidence
  - Evaluation metrics count these hallucinations as errors

Why it matters:
  - Hallucinated rooms inflate graph similarity scores falsely
  - Benchmark cannot distinguish between correct and confabulated layouts
  - Direct floor plan accuracy becomes impossible to assess

Source Quote:
  "A notable problem is the tendency of MLLMs to produce responses that are not
  factually grounded in the visual input, commonly referred to as hallucinations,
  leading to inaccuracies such as incorrect descriptions of non-existent visual
  elements. This undermines the trustworthiness of MLLMs in many practical
  applications."
  — MERLIM-class analysis (49qqV4NTdy)

How to test:
  For each room/door in model output, verify it appears in at least one input
  photo. Count false positives (invented features). Should be zero.


WEAKNESS #4: VISUAL INSTRUCTION FOLLOWING FAILURE
───────────────────────────────────────────────────
Title: Open-source MLLMs cannot follow instructions embedded in visual format

What happens:
  - If apartment images contain annotations (e.g., "Kitchen", arrows)
  - If floor plan hints/overlays embedded in images
  - Open-source models ignore or misparse visual instruction text
  - Only closed-source/finetuned models handle visual instructions

Why it matters:
  - If Blueprint-Bench includes any visual cues in images, most models fail
  - "Text in image" recognition is poor for open-source MLLMs
  - Benchmark relies on text-only instructions, but real-world uses visual cues

Source Quote:
  "open and closed source MLLMs are robust to the position of textual instruction
  in the image. However, models that haven't seen visual instruction training are
  not robust enough at visual-modality instruction following. After being tuned
  on the proposed VIM training dataset, open-source models demonstrate better
  instruction following capability."
  — PIXELATED INSTRUCTIONS (DiRJUdmZoK)

How to test:
  Add text/annotations to apartment images (e.g., room labels). Re-run
  open-source models. Performance should NOT degrade if models truly understand
  spatial layout. Degradation = visual instruction failure.


WEAKNESS #5: INSUFFICIENT VISUAL INFORMATION UTILIZATION
──────────────────────────────────────────────────────────
Title: Models fail to maintain and reference spatial details during generation

What happens:
  - Apartment images clearly show room boundaries, doors, adjacencies
  - Model's image encoder captures this information
  - During floor plan generation, model fails to reference captured details
  - Model generates impossible layouts despite visual evidence
  - Example: Two rooms visually connected, model generates disconnected graph

Why it matters:
  - Problem isn't lack of information, but failure to use available info
  - Bottleneck is in decoding/reasoning, not perception
  - Needs better spatial reasoning strategies, not better image encoders

Source Quote:
  "To help LLaVA-1.5 keep the visual information during decoding, we try an
  alternative decoding algorithm, Multi-Modal Mutual-Information Decoding (M3ID),
  leading to performance gain (+6%). This underscores the potential to enhance
  model performance by employing better extraction and utilization techniques
  with the same pretrained image encoder."
  — MMVP/VLM Action Games (5E6VOD7W0z)

How to test:
  Ablate visual inputs: Run Model(Text only) vs Model(Text + Images).
  Performance should drop significantly without images. Small drops indicate
  models aren't using visual information effectively.


WEAKNESS #6: COMPLEX MULTI-STEP SPATIAL REASONING FAILURE
──────────────────────────────────────────────────────────
Title: Models cannot chain multiple reasoning steps needed for full floor plans

What happens:
  - Floor plan generation requires: identify rooms → find adjacencies →
    locate doors → resolve ambiguities → synthesize complete graph
  - Models fail to maintain context across all steps
  - Performance degrades as apartment complexity increases (5+ rooms)
  - Models succeed on simple apartments, fail on complex ones

Why it matters:
  - Even GPT-4 achieves only 60% on complex instruction-following benchmarks
  - Indicates fundamental limitation in multi-step spatial reasoning
  - Blueprint-Bench with diverse apartment complexities will expose this

Source Quote:
  "Even GPT-4, the strongest baseline, achieves only 60% pass rate [on complex
  instruction-following benchmarks], indicating that complex instruction following
  remains a fundamental limitation of current models."
  — BigCodeBench analysis (1,140 complex tasks)

How to test:
  Bin apartments by room count: (2-3 rooms, 4-5 rooms, 6+ rooms).
  Calculate accuracy per complexity bin. Should remain stable.
  Large drops on complex apartments = reasoning failure.

Info Underuse:        Visual info available but not used during generation
Complexity:           Simple apartments OK, complex ones fail
