SUMMARY: Weakness Patterns in Related Papers for Selective Fine-Tuning on OOD Generalization
================================================================================================

PAPERS ANALYZED: 9 papers from ICLR 2025 covering fine-tuning, generalization, and parameter-efficient methods

TOP WEAKNESS PATTERNS (Frequency & Impact)
============================================

1. LIMITED EVALUATION SCOPE [Frequency: 8/9 papers]
   - Single benchmark family or few datasets
   - Narrow baseline comparisons
   - Task-specific evaluation
   Impact: Critical - Directly cited in low ratings (3-5/10)
   Examples: SIGnAL (only text classification), VisCE² (only caption evaluation)

   RECOMMENDATION: Test on 3-5 diverse benchmarks + multiple OOD settings

2. INSUFFICIENT ABLATION STUDIES [Frequency: 6/9 papers]
   - No component-wise analysis
   - Missing hyperparameter sensitivity
   - Lack of design choice justification
   Impact: High - Reviewers explicitly request ablations
   Examples: SIGnAL (no PPO ablation), RMP-SAM (no task conflict analysis)

   RECOMMENDATION: Comprehensive ablation on modules, learning rates, layers, data efficiency

3. LACK OF MECHANISTIC EXPLANATION [Frequency: 5/9 papers]
   - Why method works unclear
   - Limited representation analysis
   - Missing theoretical insight
   Impact: Very High - Directly affects contribution scores
   Examples: GraphAny (why transfers across graphs?), BDHS (why masks work?)

   RECOMMENDATION: Provide clear analysis of what modules learn and why selective helps OOD

4. TASK/SETTING SPECIFICITY [Frequency: 7/9 papers]
   - Methods work only on specific domains
   - Narrow evaluation protocols
   - Unclear cross-domain applicability
   Impact: High - Limits novelty and generalization claims
   Examples: 10kBEqYKKN (only binary classification), VisCE² (only captions)

   RECOMMENDATION: Evaluate on diverse reasoning types; test new rule combinations

5. WEAK BASELINE COMPARISONS [Frequency: 6/9 papers]
   - Missing related approaches
   - Unfair experimental setups
   - Limited SOTA baselines
   Impact: High - Undermines result credibility
   Examples: SIGnAL (no synthesizing methods), 49qqV4NTdy (only LLaVA)

   RECOMMENDATION: Compare against LoRA, BitFit, adapters, full fine-tuning with fair setup

6. INSUFFICIENT OOD/GENERALIZATION ANALYSIS [Frequency: 7/9 papers]
   - Limited OOD evaluation
   - No distribution shift analysis
   - Missing module importance analysis
   Impact: Very High for OOD papers
   Examples: 10kBEqYKKN (no OOD evaluation), GraphAny (inconsistent across datasets)

   RECOMMENDATION: Explicit OOD protocol, boundary characterization, failure analysis

KEY PAPERS TO LEARN FROM
=========================

HIGH-RATING PAPERS (6-8/10):
- GraphAny (1Qpt43cqhg): Despite issues, gets 6-8 through comprehensive evaluation on 31 datasets
- RMP-SAM (1pXzC30ry5): Gets 8/10 despite limited novelty due to extensive experiments

LOW-RATING PAPERS (3-5/10):
- SIGnAL (0YkZe9nwiC): Only Figure 3 results, no ablation → 3/10
- VisCE² (2iPvFbjVc3): Limited novelty, task-specific, no design analysis → 3-5/10

CRITICAL SUCCESS FACTORS FOR 6-8/10 RATING
==========================================

✓ Multiple benchmark datasets (3-5 different benchmarks)
✓ Comprehensive ablation studies (component, hyperparameter, design choice)
✓ Fair baseline comparisons (including full fine-tuning and related methods)
✓ Clear mechanistic explanation (why it works, what modules learn)
✓ Explicit OOD/generalization analysis (new tasks, distribution shifts)
✓ Failure case analysis (when and why method fails)
✓ Clear presentation (explicit scope, methodology, related work)

ANTI-PATTERNS TO AVOID
=======================

DON'T:
- Evaluate on single benchmark family → Don't be SIGnAL
- Skip ablation studies → Don't be VisCE²
- Leave "why it works" unexplained → Don't be GraphAny
- Use only weak baselines → Don't be SIGnAL
- Design for single task type → Don't be VisCE²
- Avoid failure case discussion → Don't be 10kBEqYKKN
- Cherry-pick favorable settings → Don't be GraphAny

DO:
- Test on diverse reasoning types and OOD settings
- Provide thorough component ablations
- Explain mechanism: which modules matter, why selective helps OOD
- Compare against full fine-tuning, LoRA, BitFit, adapters
- Analyze when method works/fails
- Present limitations explicitly
- Use proper statistical testing

SPECIFIC RECOMMENDATIONS FOR OOD FINE-TUNING PAPER
==================================================

Evaluation:
□ Test on 3-5 reasoning benchmarks (composition, arithmetic, symbolic, etc.)
□ Multiple OOD settings: new rules, distribution shifts, task combinations
□ Explicit train/test split with held-out rules
□ Statistical significance testing with confidence intervals

Baselines:
□ Full fine-tuning (critical baseline)
□ LoRA fine-tuning
□ BitFit
□ Adapter-based fine-tuning
□ Ensure comparable computational budgets
□ Fair hyperparameter tuning for all methods

Ablations:
□ Module selection sensitivity: which modules matter?
□ Learning rate: selective vs uniform
□ Layer depth: which layers to fine-tune?
□ Data efficiency: how much data needed?
□ Component contribution: each piece's impact
□ Hyperparameter sweep: sensitivity analysis

Mechanistic Analysis:
□ Why selective fine-tuning helps OOD? (Clear explanation)
□ Representation changes in fine-tuned modules
□ Module functionality analysis
□ Comparison with full fine-tuning differences
□ Theoretical insight or empirical patterns

Generalization:
□ Cross-task transfer analysis
□ New rule generalization capability
□ Boundary characterization: when does it work/fail?
□ Multiple domain evaluation
□ Failure case examples and analysis

RATING PREDICTION BASED ON ANALYSIS
====================================

With implementation of recommendations:
- 3-5 benchmarks + fair baselines + good ablations → 6/10 baseline
- + mechanistic explanation + OOD analysis → 7/10
- + comprehensive framework + failure analysis → 8/10

WITHOUT recommendations (like reviewed papers):
- Limited evaluation + weak baselines → 3/10
- + bad presentation → 2-3/10

MOST CRITICAL ELEMENTS (Don't Skip!)
=====================================

1. MECHANISTIC EXPLANATION - Why selective helps OOD (cited in 5 papers as critical)
2. COMPREHENSIVE EVALUATION - Multiple benchmarks, OOD settings (cited in 8 papers)
3. FAIR BASELINES - Proper comparison setup (cited in 6 papers)
4. ABLATION STUDIES - Component analysis (cited in 6 papers)
5. GENERALIZATION ANALYSIS - Boundary and failure characterization (cited in 7 papers)
